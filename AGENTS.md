# AGENTS.md

V.A.U.L.T. gateway, Specification Draft v3.3.2. This file is the single source of truth for project invariants, package boundaries, and PS-5 rules. Every human or AI contributor must read it before changing code, tests, docs, or UI.

Scope at W2 (Step 4, interface freeze): everything from Step 3.6 (locked environment, neutral `contracts/` package, attacker isolation guard, PS-5 linter, `app/config.py`, `app/secret_derivation.py`, hardened `telemetry/` SQLite writer) plus the 3 remaining pre-freeze audit findings closed (telemetry column verification, record cross-field rules, PS-5 binary list and curated multilingual data paths) and the W2 frozen interfaces: `InspectionBundle` schema and builder (IP-1, IP-2), IP-5 cache key formats, objective, translation-table and manifest schemas, the system-prompt and canary/PII manifest builder (PS-2, PS-3, PS-4), the canonical request schema (PS-1), and the FastAPI gateway shell with the streaming 128 KiB body cap (TM-R1) and the uniform 503 (TM-R6). Step 2.5 Findings 3, 4, 5 stay deferred until layers and harness exist. No defense layer (L1 to L4), sanitizer, Groq client, or `harness/` runtime logic exists yet; an admitted request fails closed with the uniform 503, logged as `Error` / `upstream_error`.

Label convention: `[Spec ID]` marks a rule taken from the spec text. `[Project Decision, extends <ID>]` marks a stricter choice made by this project that the spec permits but does not state verbatim.

## Invariant Rules

1. [IP-7, IP-8, RT-V6] Runtime, Storage & Telemetry Accounting: Python 3.11, FastAPI, Pydantic v2, httpx. Run a single uvicorn worker (`--workers 1`) [Project Decision, extends IP-7: IP-7 itself specifies a bounded threadpool with a semaphore and queue limit, default one worker per physical core; the single process keeps one in-memory queue and one SQLite writer]. Store SQLite databases on local disk (never synced folders) with `journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=5000`, written by a single writer thread fed from an in-memory queue. Initialize the SQLite schema and `PRAGMA user_version = 1` inside a single atomic transaction (`BEGIN IMMEDIATE ... COMMIT`). Increment `written_count` ONLY after `COMMIT` succeeds (failed commits increment `failed_count`), count still-queued records abandoned on unexpected writer death in `lost_count`, and treat `_stop_enqueued` under lock as closed immediately once `close()` begins so `produced == written + dropped + failed + lost` always holds. At the end of every measured run, `harness/` must assert `produced == written + dropped + failed + lost` and `dropped == failed == lost == 0`. On every startup, including when `PRAGMA user_version` already matches, the writer compares `PRAGMA table_info` of every managed table (`request_logs`, `shadow_records`) with the current schema (column names, declared types, `NOT NULL`, primary key) and fails fast on a missing table or any missing, unexpected, or mismatched column, before any insert. It never migrates or recreates tables in place.

2. [§2.7, §3.9] Target Model Pinning: `TARGET_MODEL` is checked against Groq's active model list at startup; fail fast if missing. `PROBE_CANDIDATES` are `openai/gpt-oss-20b`, `qwen/qwen3.8-27b` (non-thinking instruct mode), and `openai/gpt-oss-120b`. Set `ALLOW_MODEL_FAILOVER=false` so runtime failover never mixes models mid-experiment. All Groq calls must go through a single client module.

3. [PS-1, CA-1, CA-2, CA-3, TM-R1] Single-Turn Request Schema & Streaming Body Cap: Use one canonical request schema (`extra="forbid"`): `user_prompt: str` (max 4,000 chars), optional `aegis_context: list[ContextDocument]` (config defaults: max 4 docs, max 1,500 chars/doc), and `stream: bool = False`. Reject `stream=true`, multi-turn history, extra fields, client-supplied `system`/`tool` roles, or oversized payloads with uniform HTTP 503. Cap raw HTTP body size at 128 KiB (131,072 bytes) by counting bytes as chunks arrive in ASGI middleware BEFORE JSON parsing.
    - `app/schemas.py` uses strict types (no `"true"` to `True` or number to string coercion). Document ids follow the contracts identifier pattern (no `|`) and are unique per request [Project Decision, extends PS-1, PS-3: each id derives its own nonce].
    - `app/middleware.BodyCapMiddleware` is pure ASGI (never `BaseHTTPMiddleware`): a `Content-Length` above the cap, malformed, or conflicting is refused before any body byte is read; otherwise reading stops at the first chunk that pushes the running total past 131,072 bytes (chunked bodies and lying `Content-Length` included). Exactly 131,072 bytes is accepted, 131,073 refused. An accepted body (at most 128 KiB in memory) is replayed to the app unchanged.

4. [IP-1, IP-2, TM-R1] InspectionBundle & Per-View Window Limit: `raw_view` is untouched. `decoded_view` applies Unicode NFKC, strips Unicode category `Cf`, and decodes Base64/hex (depth 2, >=20 chars or padded, >=85% printable UTF-8, including whitespace-joined adjacent candidates). Cap `decoded_view` at 4,000 chars (reuses `MAX_PROMPT_CHARS`). Slice both views into character windows (600 chars, stride 300). If a window exceeds a layer's tokenizer limit (256 for MiniLM, 512 for DeBERTa), split it into sub-windows BEFORE checking the 16-window per-view limit so `truncation_count` remains `0`. Refuse with uniform HTTP 503 ONLY if `decoded_view` > 4,000 chars or windows in EITHER view exceed 16 after sub-window splitting. Never truncate.
    - Frozen schema `contracts/inspection.py` (`InspectionBundle`, `TextWindow`, `WindowPlan`, `DecodeStep`, `CapExceeded`); builder `app/inspection.py`. The schema itself rejects any window whose text is not its view slice, any unscanned gap or tail, more than `max_windows_per_view` windows, and `truncation_count != 0`.
    - Decoding: hex is tried before Base64; a candidate token is a Base64-alphabet run of 20+ characters or one ending in `=`; only adjacent candidates (whitespace-separated) are tried joined; depth 2 means at most two passes; NFKC plus `Cf` strip runs on the input, on each decoded segment, and at the end of each pass. Not implemented, by spec: cross-script homoglyph folding (optional H-NORM, §3.6), URL percent-decoding, HTML entities.
    - Sub-window splitting [Project Decision, extends IP-2]: each consumer registers a `TokenizerLimit` (name, limit, `count_tokens` including special tokens); a window above the limit is cut into the fewest equal contiguous pieces that all fit, identical pieces from overlapping parents count once, and the 16-window cap is checked per view per tokenizer after splitting. The result is one `WindowPlan` per tokenizer.
    - A cap breach returns `CapExceeded` (`blocked_by` `"decoded_cap"` or `"window_cap"`), logged as `Blocked-ingress`. `bundle_version` is a SHA-256 over every bundle parameter, the tokenizer limits, and `unicodedata.unidata_version`; `prompt_hash` is `canonical_hash({"raw_view": raw_view})`.

5. [IP-9, §3.2, §2.5] Neutral Contracts Package: Shared types live in `contracts/` and import only stdlib and pydantic (zero project imports): canonical gateway modes and `resolve_derivation_mode()` in pure-stdlib `contracts/modes.py` (`GatewayMode`, `DETERMINISTIC_MODES`, `RANDOM_MODES`, so `contracts/` and `app/config.py` never import `app/secret_derivation.py`), frozen `LayerResult` (`layer`, `view`, `per_window_scores` as an immutable tuple, `overall_score`, `verdict` in `allow|block|timeout|error`, `latency_ms`, `truncation_count` == 0, `error_message`), `Outcome(StrEnum)` (`Blocked-ingress`, `Admitted-refused`, `Egress-saved`, `Success`, `Error`), `EgressAction = Literal["none", "masked", "blocked"]`, frozen `RequestLogRecord` (RT-V6 fields plus `blocked_by` using canonical `"L4"` for egress, `egress_variant`, `egress_action` defaulting to `"none"`, `timeout_policy`, `cache_hit`, `model_id`), frozen `ShadowRecord` (IP-4; required non-empty `layer_version`, `bundle_version`, `chroma_version`; `shadow_full_e2e` requires `target_called=True` and all four variants X0 to X3 sharing one `response_hash` and `manifest_id`), frozen `EgressVariantRecord` (required `response_hash` and `manifest_id`, the IP-5 join keys with `variant`, plus `egress_action` defaulting to `"none"`), all SHA-256 fields constrained to `^[0-9a-f]{64}$`, `canonical_hash()` (deterministic JSON with `ensure_ascii=False`, `allow_nan=False`, UTF-8 `surrogatepass` encoding, SHA-256 via `hashlib`; never use Python `hash()`), shared synced-folder path detection in `contracts/paths.py` (`synced_folder_component`), and the typed `TelemetrySink` Protocol (`record_request(RequestLogRecord)`, `record_shadow(ShadowRecord)`) that `app/` layers, middleware, and request handlers call instead of importing `telemetry/`.
    - `target_called` semantics (§3.2, IP-4, IP-5): `target_called=True` means "admitted to the target" even on a response-cache hit (`cache_hit=True`), while `cache_hit` records whether an upstream API call occurred (`False`) or was served from cache (`True`).
    - Strict `outcome` vs `blocked_by` mapping (§3.2): security layer blocks (`L1`, `L2`, `L3`) and input/view/window caps (`body_cap`, `schema_validation`, `decoded_cap`, `window_cap`) map ONLY to `Outcome.BLOCKED_INGRESS` (`target_called=False`); operational and policy faults (`load_shed`, `p_closed`, `timeout`, `upstream_error`, `internal_error`) map ONLY to `Outcome.ERROR` (never `Blocked-ingress`, so overload shedding never inflates block rate); HTTP routing misses (`not_found`, `method_not_allowed`) are not attack outcomes and are excluded from `BlockedBy`; `Outcome.EGRESS_SAVED` requires `egress_variant` in `X1..X3`, `target_called=True`, and `egress_action` in `("masked", "blocked")` (with `blocked_by=None` when `"masked"`, and L4 blocking evidence when `"blocked"`).
    - Layer evidence and oracle consistency (§3.2): `Blocked-ingress` with `blocked_by` in `L1..L3` requires a `LayerResult` of that exact layer with `verdict="block"` (mirroring the L4 rule). When `oracle_result` is recorded, `Success` requires `True` and `Admitted-refused` / `Egress-saved` require `False`. In `EgressVariantRecord`, `verdict="block"` holds if and only if `egress_action="blocked"`, and `X0` (no scan) is always `verdict="allow"`, `egress_action="none"`.
    - `UNPARSED_PROMPT_HASH` (`canonical_hash({"raw_view": None})`) is the `prompt_hash` of a request refused before a prompt was parsed (body cap, schema violation, fault before parsing).
    - W2 frozen contracts added at Step 4: `contracts/inspection.py` (IP-1, IP-2), `contracts/cache_keys.py` (IP-5), `contracts/datasets.py` (objective file, translation table, dataset manifest, `CanaryPIIManifest`, the single `PII_ENTITY_TYPES` tuple). Identifiers in these schemas exclude `|`, the PS-3 HMAC field separator [Project Decision, extends PS-3].

6. [PS-2, PS-3, TM-S3, D-PII] Domain-Separated Secrets: In all deterministic modes (`eval`, `shadow_ingress_only`, `shadow_full_e2e`), refuse to start if `HMAC_SECRET` (after stripping) is empty, shorter than 16 characters (`MIN_HMAC_SECRET_CHARS = 16`), or equals the exact placeholder `vault_dev_secret_change_me` from `.env.example` [Project Decision, extends PS-3: adds a 16-character minimum length in deterministic modes]. `mode` is required (no default) on every `derive_*` function and mapped through `contracts.modes.resolve_derivation_mode()`. Derive secrets with domain separation: canary via `HMAC-SHA256(secret, f"canary|{objective_id}")`, synthetic PII via `HMAC-SHA256(secret, f"pii|{objective_id}|{entity_type}")` seeding isolated pinned `Faker` (`faker==30.1.0`, `PHONE_NUMBER` validated via `phonenumbers` US), and sanitizer nonce (`<EXTERNAL_DATA_{nonce}>`) via full 64-hex (256-bit) `HMAC-SHA256(secret, f"nonce|{objective_id}|{doc_id}")`. In `production`/`demo` mode, use `secrets.token_hex(16)`. Keep shared defensive system-prompt text first and per-objective secrets last.
    - `app/prompting.py` is the single system-prompt, manifest and message builder for every configuration including C0 and D0 (PS-4, TM-S4): `SHARED_DEFENSIVE_INSTRUCTIONS` first, then `CANARY:` and the five planted PII values (sorted by entity type) last; `build_messages` returns `[system, user]` only (CA-3), and sanitizer-wrapped `<EXTERNAL_DATA_{nonce}>` documents follow the user prompt in the user message. The configuration, seed, and mode are not builder inputs, so the IP-5 target-response key repeats across configurations and seeds.
    - `CanaryPIIManifest` is in-process only and never written to disk. `manifest_id` is a SHA-256 over objective ID, canary, planted values and system-prompt hash (not the mode), so all deterministic modes share one manifest ID; secret fields are hidden from `repr`.

7. [TM-R6] Global Uniform 503 Refusal: Register global FastAPI exception handlers for `RequestValidationError` (422), `StarletteHTTPException` (404/405), and unhandled exceptions so every block or error returns identical status `503`, identical headers, and body `{"detail": "Service Unavailable. Request blocked by security policy."}`. Read `X-Trial-ID` for server logging only; NEVER echo `X-Trial-ID` in responses. Every client sets `max_retries=0`.
    - The fixed header set is exactly `content-type: application/json`, `content-length: 70`, `cache-control: no-store`, and the body bytes are the spec text verbatim (`app/errors.py`). `app.middleware.FailClosedMiddleware` is the outermost middleware and converts any exception raised below it into the uniform 503, so Starlette's default 500 page is unreachable. OpenAPI, `/docs` and `/redoc` are disabled. Run with `uvicorn app.main:create_app --factory --workers 1 --no-server-header --no-date-header` so the server adds no varying headers.
    - Server-side labels: schema and field-cap violations log `schema_validation`; routing misses (404, 405) are not logged as attack outcomes (§3.2); unhandled exceptions log `internal_error`. Logging never changes the response, and each request is logged at most once.
    - Endpoints [Project Decision, the spec names a public gateway endpoint but no path]: `POST /v1/chat` (canonical request, `{"content": str}` on success), `GET /healthz` (liveness, constant body), `GET /readyz` (uniform 503 when the telemetry sink is unhealthy).

8. [IP-6, IP-7, TM-R4] Threadpool, Atomic ChromaDB & Egress/Reasoning Rule: Run all layer calls in a bounded threadpool and shed overload with 503 (IP-7). Set ONNX `intra_op_num_threads=1` and `inter_op_num_threads=1` [Project Decision, extends IP-7: keeps per-call CPU use predictable inside the bounded pool; not verbatim IP-7 text]. Read the immutable ChromaDB collection version pointer once per request. Cache raw provider JSON including `reasoning`. L4 egress scanning (IP-6) runs ONLY in egress variants `X1` and above: `X0` performs no egress scan; `X1` runs pattern-only Presidio; `X2` adds exact canary matching; `X3` adds the decoded-text and similarity leak check (§2.1). Where it runs, L4 scans both `content` and `reasoning` using pattern-only Presidio (`EMAIL_ADDRESS`, `PHONE_NUMBER`, `CREDIT_CARD`, `US_SSN`, `IBAN_CODE`, no spaCy NER) and, from `X2`, canary matching; `reasoning` findings are logged and `reasoning` is stripped, while L4's block verdict is determined solely by `content`. [TM-R4] Any L4 timeout or error ALWAYS fails closed with uniform HTTP 503, independent of `TIMEOUT_POLICY`. Return client-visible responses strictly as `{"content": str}`. E4 uses a local fixed-delay stub upstream.

9. [PS-2, §5.2] Strict Attacker Isolation: Oracles and evaluation runners live in `harness/`. `attacker/` talks only to the public HTTP endpoint and must NEVER import `app`, `telemetry`, `harness`, `HMAC_SECRET`, manifests (`data/manifests`), caches (`data/cache`), or logs (`data/logs`), nor the storage and model stacks (`sqlite3`, `chromadb`, `onnxruntime`, `presidio`, `sentence_transformers`) (enforced by AST unit test). Runtime requirement: the harness must launch `attacker/` with a scrubbed environment (explicit allowlist of variables) so `HMAC_SECRET` is never inherited from the parent process.

10. [§5.5] Verification Discipline: Every implemented Spec ID must have a unit test. Frozen interfaces (end of W2, including package layout) change only via changelog and spec update. `scripts/ps5_lint.py` must exit 0 before every commit.

11. [PS-5, Anti-Vibecode Engineering Standard] Explicitly ban all 20 AI-cliche patterns across code, comments, logs, docs, and the W15 SOC Admin Monitor UI: (1) purple-to-blue gradient, (2) gradient hero text, (3) emojis in headings/logs/comments, (4) Inter font everywhere, (5) colored border cards, (6) glassmorphism cards, (7) low-contrast dark mode, (8) 3 icon boxes in a row, (9) badge above the headline, (10) Lucide icons everywhere, (11) untouched shadcn UI, (12) fade-in on scroll, (13) cursor-following beam, (14) buttons fade on hover, (15) inconsistent spacing, (16) em dashes everywhere, (17) generic buzzword copy, (18) serif italic accents, (19) Space Grotesk + Instrument Serif, (20) grain over a gradient. Build the W15 monitor as a flat, high-contrast utilitarian SOC console (1px solid borders, tabular monospace metrics, strict green/amber/red status indicators).
    - [Project Decision, extends PS-5] Spec pattern 16 names em dashes only; this project also bans en dashes (U+2013) everywhere, ASCII control characters (`ord(ch) < 0x20` except `\n` and `\r`, plus `0x7F` DEL), all Unicode format characters (`unicodedata.category(ch) == "Cf"`, including BOM `U+FEFF`, zero-width spaces `U+200B`, and bidi controls `U+202E`, `U+2066`), and any non-UTF-8 file outside the explicit binary suffix allowlist. `scripts/ps5_lint.py` enforces all of these checks.
    - Plain utilitarian status glyphs (U+2713, U+2717, U+2715, U+25CF, U+25A0, box-drawing, ASCII and arrow symbols) are allowed in the W15 SOC console and are not flagged. True pictographs and emoji (including U+2705, U+274C, U+26A0, and the emoji presentation selector) remain banned.
    - The linter skips `data/raw/`, `data/cache/`, `results/`, `.venv/`, `.git/`, `chroma_db/`, `__pycache__/`, binary files (`BINARY_SUFFIXES`: images, PDF, `.docx`, `.xlsx`, `.pptx`, `.mp4`, model weights including `.onnx`, `.gguf`, `.tflite`, `.h5`, serialized data `.pkl`, `.pickle`, `.joblib`, `.parquet`, `.feather`, `.npy`, databases, archives including `.7z`, `.rar`, `.xz`, `.bz2`, `.tgz`, compiled code, and fonts including `.otf`), and any file larger than 5 MiB.
    - Curated multilingual data paths [Project Decision, extends PS-5]: `data/translations/` (the spec-tracked translation table, §2.7, §3.4) and `data/benign/` (the hand-curated, tracked D-BEN-2 set, which includes Arabic translation requests, §2.2; the spec names no directory for it, so this path is fixed here). Files there are dataset text, so the PS-5 typography checks (emoji, em and en dashes) do not apply, but they must be valid UTF-8, contain no ASCII control characters, and contain no `Cf` character except `CURATED_ALLOWED_FORMAT_CHARS` = ZWNJ `U+200C`, LRM `U+200E`, RLM `U+200F`, Arabic letter mark `U+061C`. BOM, `U+200B`, `U+200D`, bidi embeddings, overrides and isolates, and the tag block still fail there. Everywhere else, including `data/manifests/` and `data/objectives/` (objective files: English base queries, §3.4), the strict rule bans every `Cf` character. `contracts/datasets.py` applies the same allowlist to `TranslationEntry.text`, and a unit test keeps the two sets identical.
    - Text-level UI pattern checks (`linear-gradient`, `backdrop-filter`, `Inter`, `Space Grotesk`, `Instrument Serif`, `lucide`) will be added to `scripts/ps5_lint.py` before W15.
