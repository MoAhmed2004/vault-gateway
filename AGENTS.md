## Invariant Rules

1. [IP-7, IP-8, RT-V6] Runtime, Storage & Telemetry Accounting: Python 3.11, FastAPI, Pydantic v2, httpx. Run a single uvicorn worker (`--workers 1`) [Project Decision, extends IP-7: IP-7 itself specifies a bounded threadpool with a semaphore and queue limit, default one worker per physical core; the single process keeps one in-memory queue and one SQLite writer]. Store SQLite databases on local disk (never synced folders) with `journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=5000`, written by a single writer thread fed from an in-memory queue. Initialize the SQLite schema and `PRAGMA user_version = 1` inside a single atomic transaction (`BEGIN IMMEDIATE ... COMMIT`). Increment `written_count` ONLY after `COMMIT` succeeds (failed commits increment `failed_count`), count still-queued records abandoned on unexpected writer death in `lost_count`, and treat `_stop_enqueued` under lock as closed immediately once `close()` begins so `produced == written + dropped + failed + lost` always holds. At the end of every measured run, `harness/` must assert `produced == written + dropped + failed + lost` and `dropped == failed == lost == 0`. On every startup, including when `PRAGMA user_version` already matches, the writer compares `PRAGMA table_info` of every managed table (`request_logs`, `shadow_records`) with the current schema (column names, declared types, `NOT NULL`, primary key) and fails fast on a missing table or any missing, unexpected, or mismatched column, before any insert. It never migrates or recreates tables in place.

2. [§2.7, §3.9] Target Model Pinning: `TARGET_MODEL` is checked against Groq's active model list at startup; fail fast if missing. `PROBE_CANDIDATES` are `openai/gpt-oss-20b`, `qwen/qwen3.8-27b` (non-thinking instruct mode), and `openai/gpt-oss-120b`. Set `ALLOW_MODEL_FAILOVER=false` so runtime failover never mixes models mid-experiment. All Groq calls must go through a single client module.
    - Implemented at Step 5A: `app/groq_client.GroqClient` is the only Groq client. Before the gateway accepts traffic, the lifespan calls `verify_models([TARGET_MODEL, *PROBE_CANDIDATES])`: a missing or inactive id, or a model list that cannot be read, raises `ModelCheckError` and startup stops (§3.9 validates each candidate id too). `UPSTREAM_MODE=groq` without `GROQ_API_KEY` is refused in `create_app`. A completion whose `model` field differs from the pin is refused as `model_mismatch`.
    - No retries anywhere (TM-R6): `httpx.AsyncHTTPTransport(retries=0)`, redirects not followed, no retry loop. `UPSTREAM_TIMEOUT_S` bounds the whole call (httpx per-phase timeouts plus an outer `asyncio.wait_for`); TM-R2 budgets exclude target time. Every upstream failure (timeout, transport, 429, 5xx, 4xx, malformed JSON including the non-standard constants `NaN`, `Infinity` and `-Infinity`, model mismatch) is `Error` / `upstream_error` with the uniform 503; error labels never carry the key or a body. Provider bytes are parsed with `json.loads(..., parse_constant=...)` that refuses the three constants (Step 5B.1 LM-1).
    - Post-target guard (TM-R6, RT-V6): any unexpected exception after the target call returned (cache write, L4 bookkeeping) is logged as `Error` / `internal_error` with `target_called=True`, the real `prompt_hash` and the actual `cache_hit`, in production and in `shadow_full_e2e`, with the uniform 503.
    - `shadow_ingress_only` never calls the target: the app builds and probes no Groq client in that tier and starts without `GROQ_API_KEY` (IP-4).
    - Target parameters (`TARGET_TEMPERATURE` 0, `TARGET_SEED`, `TARGET_MAX_TOKENS`, optional `TARGET_REASONING_EFFORT`) are part of the IP-5 target-response key. Unit tests use `httpx.MockTransport` only; no test touches the network, and `tests/conftest.py` enforces it for the whole suite (§5.5): an autouse fixture refuses every non-loopback `socket.connect` / `connect_ex`, `getaddrinfo` of a non-loopback host, and the asyncio selector and proactor `sock_connect`.

3. [PS-1, CA-1, CA-2, CA-3, TM-R1] Single-Turn Request Schema & Streaming Body Cap: Use one canonical request schema (`extra="forbid"`): `user_prompt: str` (max 4,000 chars), optional `aegis_context: list[ContextDocument]` (config defaults: max 4 docs, max 1,500 chars/doc), and `stream: bool = False`. Reject `stream=true`, multi-turn history, extra fields, client-supplied `system`/`tool` roles, or oversized payloads with uniform HTTP 503. Cap raw HTTP body size at 128 KiB (131,072 bytes) by counting bytes as chunks arrive in ASGI middleware BEFORE JSON parsing.
    - `app/schemas.py` uses strict types (no `"true"` to `True` or number to string coercion). Document ids follow the contracts identifier pattern (no `|`) and are unique per request [Project Decision, extends PS-1, PS-3: each id derives its own nonce].
    - `app/middleware.BodyCapMiddleware` is pure ASGI (never `BaseHTTPMiddleware`): a `Content-Length` above the cap, malformed (anything but 1 to 20 ASCII digits, so latin-1 superscripts such as `\xb2` and 5,000-digit values are `body_cap`, never `internal_error`), or conflicting is refused before any body byte is read; otherwise reading stops at the first chunk that pushes the running total past 131,072 bytes (chunked bodies and lying `Content-Length` included). Exactly 131,072 bytes is accepted, 131,073 refused. An accepted body (at most 128 KiB in memory) is replayed to the app unchanged.

4. [IP-1, IP-2, TM-R1] InspectionBundle & Per-View Window Limit: `raw_view` is untouched. `decoded_view` applies Unicode NFKC, strips Unicode category `Cf`, and decodes Base64/hex (depth 2, >=20 chars or padded, >=85% printable UTF-8, including whitespace-joined adjacent candidates). Cap `decoded_view` at 4,000 chars (reuses `MAX_PROMPT_CHARS`). Slice both views into character windows (600 chars, stride 300). If a window exceeds a layer's tokenizer limit (256 for MiniLM, 512 for DeBERTa), split it into sub-windows BEFORE checking the 16-window per-view limit so `truncation_count` remains `0`. Refuse with uniform HTTP 503 ONLY if `decoded_view` > 4,000 chars or windows in EITHER view exceed 16 after sub-window splitting. Never truncate.
    - Frozen schema `contracts/inspection.py` (`InspectionBundle`, `TextWindow`, `WindowPlan`, `DecodeStep`, `CapExceeded`); builder `app/inspection.py`. The schema itself rejects any window whose text is not its view slice, any unscanned gap or tail, more than `max_windows_per_view` windows, and `truncation_count != 0`.
    - Decoding: hex is tried before Base64; a candidate token is a Base64-alphabet run of 20+ characters or one ending in `=`; only adjacent candidates (whitespace-separated) are tried joined, as contiguous runs scanned forward from each position with no piece limit, the longest valid run winning (a neighbouring 20+ character word or path, or a payload split into any number of pieces, cannot hide it). The scan is incremental: Base64 (4 characters to 3 bytes) and hex (2 to 1) decode block by block into a strict incremental UTF-8 decoder, each token is decoded once per start position, and a start stops scanning as soon as its bytes are not UTF-8 or the 85% printable ratio is unreachable even if every remaining character were printable. A run that stops inside a group must end on a Base64 block boundary or `=` padding so the tokens after it start on a fresh block; if no such stop exists the longest run is used anyway (an unpadded payload before an ordinary word), and its continuation is joined without the whitespace gap. Worst case measured in `tests/test_inspection.py` and reported in `CHANGELOG.md`: depth 2 means at most two passes; NFKC plus `Cf` strip runs on the input, on each decoded segment, and at the end of each pass. Not implemented, by spec: cross-script homoglyph folding (optional H-NORM, §3.6), URL percent-decoding, HTML entities.
    - Sub-window splitting [Project Decision, extends IP-2]: each consumer registers a `TokenizerLimit` (name, limit, `count_tokens` including special tokens; the name is checked against `contracts.inspection.TokenizerName` at construction, so bad config fails at startup); a window above the limit is cut into the fewest equal contiguous pieces that all fit, identical pieces from overlapping parents count once, and the 16-window cap is checked per view per tokenizer after splitting. The result is one `WindowPlan` per tokenizer.
    - A cap breach returns `CapExceeded` (`blocked_by` `"decoded_cap"` or `"window_cap"`), logged as `Blocked-ingress`. `bundle_version` is a SHA-256 over `BUNDLE_ALGORITHM_REVISION` (3 since Step 4.6), every bundle parameter including the join-scan mode, the tokenizer limits, and `unicodedata.unidata_version`; `prompt_hash` is `canonical_hash({"raw_view": raw_view})`, and the `InspectionBundle` schema rejects any other value.

5. [IP-9, §3.2, §2.5] Neutral Contracts Package: Shared types live in `contracts/` and import only stdlib and pydantic (zero project imports): canonical gateway modes and `resolve_derivation_mode()` in pure-stdlib `contracts/modes.py` (`GatewayMode`, `DETERMINISTIC_MODES`, `RANDOM_MODES`, so `contracts/` and `app/config.py` never import `app/secret_derivation.py`), frozen `LayerResult` (`layer`, `view`, `per_window_scores` as an immutable tuple, `overall_score`, `verdict` in `allow|block|timeout|error`, `latency_ms`, `truncation_count` == 0, `error_message`), `Outcome(StrEnum)` (`Blocked-ingress`, `Admitted-refused`, `Egress-saved`, `Success`, `Error`), `EgressAction = Literal["none", "masked", "blocked"]`, frozen `RequestLogRecord` (RT-V6 fields plus `blocked_by` using canonical `"L4"` for egress, `egress_variant`, `egress_action` defaulting to `"none"`, `timeout_policy`, `cache_hit`, `model_id`), frozen `ShadowRecord` (IP-4; required non-empty `layer_version`, `bundle_version`, `chroma_version`; `shadow_full_e2e` requires `target_called=True` and all four variants X0 to X3 sharing one `response_hash` and `manifest_id`), frozen `EgressVariantRecord` (required `response_hash` and `manifest_id`, the IP-5 join keys with `variant`, plus `egress_action` defaulting to `"none"`), all SHA-256 fields constrained to `^[0-9a-f]{64}$`, `canonical_hash()` (deterministic JSON with `ensure_ascii=False`, `allow_nan=False`, UTF-8 `surrogatepass` encoding, SHA-256 via `hashlib`; never use Python `hash()`), shared synced-folder path detection in `contracts/paths.py` (`synced_folder_component`), and the typed `TelemetrySink` Protocol (`record_request(RequestLogRecord)`, `record_shadow(ShadowRecord)`) that `app/` layers, middleware, and request handlers call instead of importing `telemetry/`.
    - `target_called` semantics (§3.2, IP-4, IP-5): `target_called=True` means "admitted to the target" even on a response-cache hit (`cache_hit=True`), while `cache_hit` records whether an upstream API call occurred (`False`) or was served from cache (`True`).
    - Strict `outcome` vs `blocked_by` mapping (§3.2): security layer blocks (`L1`, `L2`, `L3`) and input/view/window caps (`body_cap`, `schema_validation`, `decoded_cap`, `window_cap`) map ONLY to `Outcome.BLOCKED_INGRESS` (`target_called=False`); operational and policy faults (`load_shed`, `p_closed`, `timeout`, `upstream_error`, `internal_error`) map ONLY to `Outcome.ERROR` (never `Blocked-ingress`, so overload shedding never inflates block rate); HTTP routing misses (`not_found`, `method_not_allowed`) are not attack outcomes and are excluded from `BlockedBy`; `Outcome.EGRESS_SAVED` requires `egress_variant` in `X1..X3`, `target_called=True`, and `egress_action` in `("masked", "blocked")` (with `blocked_by=None` when `"masked"`, and L4 blocking evidence when `"blocked"`).
    - Layer evidence and oracle consistency (§3.2): `Blocked-ingress` with `blocked_by` in `L1..L3` requires a `LayerResult` of that exact layer with `verdict="block"` (mirroring the L4 rule). When `oracle_result` is recorded, `Success` requires `True` and `Admitted-refused` / `Egress-saved` require `False`. In `EgressVariantRecord`, `verdict="block"` holds if and only if `egress_action="blocked"`, and `X0` (no scan) is always `verdict="allow"`, `egress_action="none"`.
    - `UNPARSED_PROMPT_HASH` (`canonical_hash({"raw_view": None})`) is the `prompt_hash` of a request refused before a prompt was parsed (body cap, schema violation, fault before parsing). A refusal after parsing (config field caps, decoded or window cap, upstream error) logs the real `canonical_hash({"raw_view": user_prompt})`.
    - W2 frozen contracts added at Step 4: `contracts/inspection.py` (IP-1, IP-2), `contracts/cache_keys.py` (IP-5), `contracts/datasets.py` (objective file, translation table, dataset manifest, `CanaryPIIManifest`, the single `PII_ENTITY_TYPES` tuple). Identifiers in these schemas exclude `|`, the PS-3 HMAC field separator [Project Decision, extends PS-3].

6. [PS-2, PS-3, TM-S3, D-PII] Domain-Separated Secrets: In all deterministic modes (`eval`, `shadow_ingress_only`, `shadow_full_e2e`), refuse to start if `HMAC_SECRET` (after stripping) is empty, shorter than 16 characters (`MIN_HMAC_SECRET_CHARS = 16`), or equals the exact placeholder `vault_dev_secret_change_me` from `.env.example` [Project Decision, extends PS-3: adds a 16-character minimum length in deterministic modes]. `mode` is required (no default) on every `derive_*` function and mapped through `contracts.modes.resolve_derivation_mode()`. Derive secrets with domain separation: canary via `HMAC-SHA256(secret, f"canary|{objective_id}")`, synthetic PII via `HMAC-SHA256(secret, f"pii|{objective_id}|{entity_type}")` seeding isolated pinned `Faker` (`faker==30.1.0`, `PHONE_NUMBER` validated via `phonenumbers` US), and sanitizer nonce (`<EXTERNAL_DATA_{nonce}>`) via full 64-hex (256-bit) `HMAC-SHA256(secret, f"nonce|{objective_id}|{doc_id}")`. Every `derive_*` function refuses `|` in each message field (`objective_id`, `entity_type`, `doc_id`) in every mode, so `("O1|d", "x")` and `("O1", "d|x")` can never derive the same value [Project Decision, extends PS-3]; the secret is the HMAC key and is not restricted. In `production`/`demo` mode, use `secrets.token_hex(16)`. Keep shared defensive system-prompt text first and per-objective secrets last.
    - `app/prompting.py` is the single system-prompt, manifest and message builder for every configuration including C0 and D0 (PS-4, TM-S4): `SHARED_DEFENSIVE_INSTRUCTIONS` first, then `CANARY:` and the five planted PII values (sorted by entity type) last; `build_messages` returns `[system, user]` only (CA-3), and sanitizer-wrapped `<EXTERNAL_DATA_{nonce}>` documents follow the user prompt in the user message. The configuration, seed, and mode are not builder inputs, so the IP-5 target-response key repeats across configurations and seeds.
    - `CanaryPIIManifest` is in-process only and never written to disk. `manifest_id` is a SHA-256 over objective ID, canary, planted values and system-prompt hash (not the mode), so all deterministic modes share one manifest ID; secret fields are hidden from `repr`.

7. [TM-R6] Global Uniform 503 Refusal: Register global FastAPI exception handlers for `RequestValidationError` (422), `StarletteHTTPException` (404/405), and unhandled exceptions so every block or error returns identical status `503`, identical headers, and body `{"detail": "Service Unavailable. Request blocked by security policy."}`. Read `X-Trial-ID` for server logging only; NEVER echo `X-Trial-ID` in responses. Every client sets `max_retries=0`.
    - The fixed header set is exactly `content-type: application/json`, `content-length: 70`, `cache-control: no-store`, and the body bytes are the spec text verbatim (`app/errors.py`). `app.middleware.FailClosedMiddleware` is the outermost middleware the gateway registers and converts any exception raised below it into the uniform 503. Starlette always wraps the user middleware in its own `ServerErrorMiddleware`, which therefore sits outside `FailClosedMiddleware`; because the global `Exception` handler is registered, Starlette uses that handler there too, so the uniform 503 is still guaranteed and the default 500 page is unreachable. OpenAPI, `/docs` and `/redoc` are disabled, and `redirect_slashes=False` makes a trailing slash (`/v1/chat/`, `/healthz/`, `/v1/chat//`) a routing miss with the uniform 503 instead of a 307 redirect. Run with `uvicorn app.main:create_app --factory --workers 1 --no-server-header --no-date-header` so the server adds no varying headers.
    - Outside TM-R6: uvicorn answers bytes it cannot parse as HTTP (malformed request line or headers) with its own plain-text 400 before the ASGI app is called, so that reply never reaches gateway code and cannot be made uniform there.
    - Server-side labels: schema and field-cap violations log `schema_validation`; routing misses (404, 405) are not logged as attack outcomes (§3.2); unhandled exceptions log `internal_error`. Logging never changes the response, and each request is logged at most once.
    - Endpoints [Project Decision, the spec names a public gateway endpoint but no path]: `POST /v1/chat` (canonical request, `{"content": str}` on success), `GET /healthz` (liveness, constant body), `GET /readyz` (uniform 503 when the telemetry sink is unhealthy).

8. [IP-6, IP-7, TM-R4] Threadpool, Atomic ChromaDB & Egress/Reasoning Rule: Run all layer calls in a bounded threadpool and shed overload with 503 (IP-7). Set ONNX `intra_op_num_threads=1` and `inter_op_num_threads=1` [Project Decision, extends IP-7: keeps per-call CPU use predictable inside the bounded pool; not verbatim IP-7 text]. Read the immutable ChromaDB collection version pointer once per request. Cache raw provider JSON including `reasoning`. L4 egress scanning (IP-6) runs ONLY in egress variants `X1` and above: `X0` performs no egress scan; `X1` runs pattern-only Presidio; `X2` adds exact canary matching; `X3` adds the decoded-text and similarity leak check (§2.1). Where it runs, L4 scans both `content` and `reasoning` using pattern-only Presidio (`EMAIL_ADDRESS`, `PHONE_NUMBER`, `CREDIT_CARD`, `US_SSN`, `IBAN_CODE`, no spaCy NER) and, from `X2`, canary matching; `reasoning` findings are logged and `reasoning` is stripped, while L4's block verdict is determined solely by `content`. [TM-R4] Any L4 timeout or error ALWAYS fails closed with uniform HTTP 503, independent of `TIMEOUT_POLICY`. Return client-visible responses strictly as `{"content": str}`. E4 uses a local fixed-delay stub upstream and runs with `CACHE_ENABLED=false` [Project Decision, extends TM-R5, IP-8]: no cache reads or writes, so every E4 request runs every layer under load and no replayed verdict hides a timeout (`CACHE_WRITES_ENABLED=false` alone is not enough for E4, because reads would still replay verdicts).
    - L4 at Step 5A (`app/layers/l4_egress.py`, `EGRESS_VARIANT`, default `X2`): Presidio findings in `content` are masked as `<ENTITY_TYPE>` (`Egress-saved` / `masked`, `blocked_by=None`); the canary in `content` blocks (`Egress-saved` / `blocked`, `blocked_by="L4"`, uniform 503). From X2, the five planted values of the in-process `CanaryPIIManifest` are also matched and masked [Project Decision, extends IP-6, PS-2]. Since Step 5B.1 (M-1, `L4_REVISION = 3`) the canary and the planted values share one character-by-character matcher in X2 and in the X3 decoded scan, the O2 "strip separators and case" rule (§3.1): each source character is folded with NFKC, then `casefold()`, every resulting character in category `Cf`, `Z*` or `P*` is dropped and only alphanumerics are kept, with a source-index map so a match masks the exact original span. Uppercase, lowercase, spaced, dotted, zero-width (`U+200B`), fullwidth, NBSP (`U+00A0`), en-dash (`U+2013`), soft-hyphen (`U+00AD`) and non-breaking-hyphen (`U+2011`) copies all match; a letter of another script still breaks a match. Presidio uses the five pattern recognizers with a 0.4 score floor [Project Decision], and email domains are validated against the bundled suffix snapshot (no network). `reasoning` findings are logged as labels in `reasoning_findings` (never values) and the field is always stripped. `presidio-anonymizer` is not in the lock file, so masking is local.
    - L4 X3 at Step 5B: X2, then (1) the decoded-text scan: the X2-masked content is decoded exactly like the ingress decoded view (NFKC, `Cf` strip, Base64/hex depth 2) and scanned again; any canary, planted value or Presidio entity found there survived masking only inside an encoding and blocks (`DECODED:<label>`); (2) the leak check against the active system prompt on the decoded content: MiniLM max cosine between response and system-prompt windows >= `X3_SIMILARITY_THRESHOLD` (0.80) or share of the system prompt's word 3-grams >= `X3_NGRAM_OVERLAP_THRESHOLD` (0.30) blocks [Project Decision, extends IP-6: the O1 oracle defaults, §3.1]. The system prompt is registered once per manifest at startup; X3 without the embedder or the reference raises and fails closed (TM-R4). The same checks run on `reasoning`, logged only.
    - L2 and L3 at Step 5B: both read their own window plan of the bundle (`minilm` 256, `deberta` 512), score the windows of both views (identical window texts once per call), take the view maximum, and block when it reaches `L2_THRESHOLD` (0.80) or `L3_THRESHOLD` (0.50) [Project Decision: defaults until tuned on validation, §2.4]; a block on either view blocks. Layer versions hash the artifact SHA-256 values, so swapping a model or tokenizer re-keys IP-5.
    - Scan mode (IP-3, IP-4; Step 5B.1 M-2): in production, demo and `eval`, L2 and L3 stop at the first window that reaches the threshold and return `block` at once (the block is checked before the deadline, so a later window hitting the deadline can never lose it); the result holds every completely scanned view plus the blocking view. In both shadow tiers they never stop early: every window of both views is scored for full telemetry. The scan mode (`early-stop` or `all-windows`) is part of the L2 and L3 layer versions, so the IP-5 cache never replays an early-stopped result into a shadow run. With a budget, windowed layers also stop between windows once their TM-R2 budget is spent (`LayerBudgetExceeded`, logged as `timeout`) so a timed-out call frees its pool thread early.
    - Late blocks (TM-R3; Step 5B.1 M-2): a layer call that returns `block` but is measured above its budget keeps the `block` (never downgraded to `timeout`), with the overrun recorded in `LayerResult.error_message`, so it blocks under P-open, P-degrade and P-closed alike. A late `allow` is still a `timeout`. Late results are not cached. A call still running at budget plus 50 ms is a timeout (its value never arrives).
    - L2 scoring (IP-2, §1.9; Step 5B.1 LM-3): ChromaDB is the persistent, versioned storage only. The first score against a version loads its embeddings once into a read-only, L2-normalized float64 matrix (rows by record id), cached per immutable `chroma_version`, and every score is the exact `max(query @ matrix.T)` in numpy; no approximate HNSW query is ever used, so the same input scores the same on every machine and at every threshold. The active version's matrix is loaded at `open()` and `activate()`.
    - MiniLM long words (IP-2, §3.6; Step 5B.1 M-3): `MiniLMEmbedder` raises the WordPiece `max_input_chars_per_word` from the shipped 100 to 600 (one window) through the `tokenizers` model attribute and verifies it by reading it back; the value is part of the embedder version, so old L2 cache keys and ChromaDB collections no longer match (rebuild the collection with `scripts/build_l2_collection.py`). A spaceless run above 100 characters is split into word pieces instead of collapsing to one `[UNK]` token.
    - ChromaDB (IP-7): `CHROMA_DB_PATH` (default `data/chroma_db`, git-ignored, local disk only), anonymized telemetry off. A version is immutable and content-addressed (SHA-256 over embedder version, label, parent and every record); the active-version pointer `active_version.json` is replaced with `os.replace` after an fsync, then the in-memory reference is swapped. `L2ThreatMemoryLayer.pin()` reads it once per request (the pipeline pins at request start). `harden_threat_memory()` builds parent plus new records as a new version and swaps the pointer, which changes the L2 key's `chroma_version` and so invalidates cached L2 verdicts. Startup fails fast when L2 is enabled and no version is active. In `eval` and both shadow tiers, startup also fails when the active version is labelled `bootstrap` or descends from a `bootstrap` version (`data/l2_seed/bootstrap.jsonl` is development and demo data only; measured runs populate L2 from S1-train, §2.4).
    - Hardening status (§3.6 step 2): `harden_threat_memory()` skips windows whose MiniLM tokens are mostly `[UNK]` (`unk_ratio >= 0.50`, Step 5B.1 M-3) and, given `forbidden_embeddings` (one row per test-split reference embedding), drops every candidate with cosine `>= max_similarity` (default 0.95) to any row. The test-split reference matrix itself is built and passed by `harness/` in W6 and W14; until then the near-duplicate guard is available but not wired to a dataset.
    - Pool (IP-7): `LAYER_POOL_WORKERS` (0 means one per physical core, via `psutil`) plus `LAYER_POOL_QUEUE_LIMIT` (32) outstanding calls; one more is refused at once as `Error` / `load_shed` with the uniform 503. Bundle builds and L1 to L4 all run there; a slot is released only when the call returns.
    - Budgets (TM-R2): each layer call runs in a worker thread and is timed there; a result above its budget is a timeout (a `block` excepted, see Late blocks), and the event loop stops waiting after budget plus 50 ms for a hung call, because asyncio timers on Windows have about 15.6 ms resolution. `L4_BUDGET_MS = 150` [Project Decision]; L1 to L4 budgets must fit `TOTAL_BUDGET_MS`. An L4 timeout logs `Error` / `timeout`, an L4 exception `Error` / `internal_error`. Budgets apply in production, demo and `eval` only; both shadow tiers build L2 and L3 with `budget_ms=None` and run L1 to L4 under a 30 s safety ceiling (`SHADOW_SAFETY_CEILING_MS`, a hang guard), never under the TM-R2 budgets, and log the true measured latency in every `LayerResult` and `ShadowRecord` (IP-4, IP-5, §1.9, §2.5; Step 5B.1 H2), so deterministic verdicts are cached and p95/p99 are never capped.
    - Total budget and the bundle build (TM-R2; closes Step 5A L2): the InspectionBundle build runs on the IP-7 pool but has no budget of its own and is not counted in `TOTAL_BUDGET_MS`. `TOTAL_BUDGET_MS` is a startup configuration check (L1 + L2 + L3 + L4 budgets must fit it), not a runtime deadline. The whole gateway time, bundle build included, is logged as `total_latency_ms` (measured from the outermost middleware) and reported by `scripts/latency_check.py`, whose cap-sized check (4,000 characters, with and without a distinct decoded view, concurrency 1) exits non-zero when any layer's p95 exceeds its budget or the bundle plus L1 to L4 p95 exceed `TOTAL_BUDGET_MS`. The TM-R2 defaults are recalibrated, against those measurements, in the upcoming latency step; Step 5B.1 does not change them.
    - Cache hits (IP-5, RT-V6; Step 5B.1 LM-2): a replayed `LayerResult` (`model_copy(update={"latency_ms": lookup_ms})`) or `EgressDecision` (`from_cache(..., latency_ms=lookup_ms)`) reports the measured cache lookup time, never the latency stored with the original computation. An egress row written under an older `l4_version` is replaced by the next write under the new version (upsert), so an `L4_REVISION` bump never leaves a key as a permanent miss; within one version the first row is kept.
    - Shadow oracle join contract (IP-4, IP-5; Step 5B.1 LM-4): `shadow_full_e2e` requires `CACHE_ENABLED=true` and `CACHE_WRITES_ENABLED=true` and writes all four egress decisions, X0 included, to the egress cache under `egress_verdict_key(response_hash, manifest_id, variant)` (production does not cache X0). `harness/` fills `EgressVariantRecord.oracle_result` in one of two ways: (a) in process, by calling `app.pipeline.run_shadow_full_e2e_detail(runtime, request)`, which returns the logged `ChatResult` plus, per variant, the verdict, `egress_action`, client-visible `content` (None when blocked or faulted) and the egress cache key, and the shared `response_hash` and `manifest_id`; or (b) offline, by reading each logged `ShadowRecord`, rebuilding the key from its `EgressVariantRecord.response_hash`, `manifest_id` and `variant`, and reading the cached decision's `content` (the L4 version must match). Variant outputs are never logged. The HTTP response of `POST /v1/chat` is unchanged.
    - Outcomes (§3.2): a released, unaltered response is `Success` with `oracle_result=None` (the gateway runs no oracle; `harness/` relabels `Success` or `Admitted-refused`). `target_called=True` from the target stage on, including a response-cache hit (`cache_hit=True`) and an upstream failure (`cache_hit=False`). In `eval` and both shadow tiers every `RequestLogRecord` and `ShadowRecord` carries `objective_id = OBJECTIVE_ID` (closes Step 5A L1).
