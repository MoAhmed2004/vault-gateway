## Invariant Rules

1. [IP-7, IP-8, RT-V6] Runtime, Storage & Telemetry Accounting: Python 3.11, FastAPI, Pydantic v2, httpx. Run a single uvicorn worker (`--workers 1`) [Project Decision, extends IP-7: IP-7 itself specifies a bounded threadpool with a semaphore and queue limit, default one worker per physical core; the single process keeps one in-memory queue and one SQLite writer]. Store SQLite databases on local disk (never synced folders) with `journal_mode=WAL`, `synchronous=NORMAL`, `busy_timeout=5000`, written by a single writer thread fed from an in-memory queue. Initialize the SQLite schema and `PRAGMA user_version` (`SCHEMA_VERSION`: 1 at the W2 freeze, 2 since Step 5C) inside a single atomic transaction (`BEGIN IMMEDIATE ... COMMIT`). Increment `written_count` ONLY after `COMMIT` succeeds (failed commits increment `failed_count`), count still-queued records abandoned on unexpected writer death in `lost_count`, and treat `_stop_enqueued` under lock as closed immediately once `close()` begins so `produced == written + dropped + failed + lost` always holds. At the end of every measured run, `harness/` must assert `produced == written + dropped + failed + lost` and `dropped == failed == lost == 0`. On every startup, including when `PRAGMA user_version` already matches, the writer compares `PRAGMA table_info` of every managed table (`request_logs`, `shadow_records`, `rate_limit_logs`, `output_sanitizer_logs`) with the current schema (column names, declared types, `NOT NULL`, primary key) and fails fast on a missing table or any missing, unexpected, or mismatched column, before any insert. It never migrates or recreates tables in place.
    - Step 5C telemetry tables (TM-R7, IP-10) [Project Decision, extends TM-R7, IP-10; `contracts/` untouched]: `rate_limit` is not a frozen `BlockedBy` value and the sanitizer verdict must stay apart from the X0 to X3 verdicts, so each has its own table on the same single-writer thread and the same `produced == written + dropped + failed + lost` accounting. `rate_limit_logs`: `timestamp_utc`, `gateway_mode`, `reason` (always `rate_limit`), `request_id`, `key_kind` (`ip`, `session`, `anonymous`), `client_key_hash` (HMAC-SHA256 under a per-process key, never the raw IP or session value), `rate_limit_rpm`, `target_called` (always 0), `method`, `path`, `trial_id`, `total_latency_ms`. `output_sanitizer_logs`: `timestamp_utc`, `gateway_mode`, `request_id`, `trial_id`, `prompt_hash`, `response_hash`, `egress_variant`, `sanitizer_version`, `mode`, `verdict` (`allow`, `block`, `neutralized`, `timeout`, `error`), `matched_families` (sorted JSON list), `latency_ms`, `error_message`; never content. `app/` hands both rows over as plain mappings through the `RateLimitSink` and `OutputSanitizerSink` Protocols in `app/audit.py`, and the sink validates every field on the producer thread before the record is counted. A version-1 database (Step 5B.1 and earlier) is refused with "schema version mismatch" and must be moved aside, never migrated.

2. [§2.7, §3.9] Target Model Pinning: `TARGET_MODEL` is checked against Groq's active model list at startup; fail fast if missing. `PROBE_CANDIDATES` are `openai/gpt-oss-20b`, `qwen/qwen3.8-27b` (non-thinking instruct mode), and `openai/gpt-oss-120b`. Set `ALLOW_MODEL_FAILOVER=false` so runtime failover never mixes models mid-experiment. All Groq calls must go through a single client module.
    - Implemented at Step 5A: `app/groq_client.GroqClient` is the only Groq client. Before the gateway accepts traffic, the lifespan calls `verify_models([TARGET_MODEL, *PROBE_CANDIDATES])`: a missing or inactive id, or a model list that cannot be read, raises `ModelCheckError` and startup stops (§3.9 validates each candidate id too). `UPSTREAM_MODE=groq` without `GROQ_API_KEY` is refused in `create_app`. A completion whose `model` field differs from the pin is refused as `model_mismatch`.
    - No retries anywhere (TM-R6): `httpx.AsyncHTTPTransport(retries=0)`, redirects not followed, no retry loop. `UPSTREAM_TIMEOUT_S` bounds the whole call (httpx per-phase timeouts plus an outer `asyncio.wait_for`); TM-R2 budgets exclude target time. Every upstream failure (timeout, transport, 429, 5xx, 4xx, malformed JSON including the non-standard constants `NaN`, `Infinity` and `-Infinity` and numbers that overflow to infinity such as `1e999` or `-1e400`, model mismatch) is `Error` / `upstream_error` with the uniform 503; error labels never carry the key or a body. Provider bytes are parsed with `json.loads(..., parse_constant=..., parse_float=...)`: the first hook refuses the three constants (Step 5B.1 LM-1), the second refuses any float that is not finite after parsing (Step 5C F1), both as `bad_json`, with the cache on or off.
    - Post-target guard (TM-R6, RT-V6): any unexpected exception after the target call returned (cache write, L4 bookkeeping) is logged as `Error` / `internal_error` with `target_called=True`, the real `prompt_hash` and the actual `cache_hit`, in production and in `shadow_full_e2e`, with the uniform 503.
    - `shadow_ingress_only` never calls the target: the app builds and probes no Groq client in that tier and starts without `GROQ_API_KEY` (IP-4).
    - Target parameters (`TARGET_TEMPERATURE` 0, `TARGET_SEED`, `TARGET_MAX_TOKENS`, optional `TARGET_REASONING_EFFORT`) are part of the IP-5 target-response key. Unit tests use `httpx.MockTransport` only; no test touches the network, and `tests/conftest.py` enforces it for the whole suite (§5.5): an autouse fixture refuses every non-loopback `socket.connect` / `connect_ex`, `getaddrinfo`, `gethostbyname`, `gethostbyname_ex` and `gethostbyaddr` of a non-loopback host, `socket.getnameinfo` and the asyncio `loop.getnameinfo` of a non-loopback socket address (Step 5C.1 L-2), `socket.sendto` and (where the platform has it) `sendmsg` to a non-loopback address, and the asyncio selector and proactor `sock_connect` and `sock_sendto` (the legacy resolver and UDP calls since Step 5C F4).

3. [PS-1, CA-1, CA-2, CA-3, TM-R1] Single-Turn Request Schema & Streaming Body Cap: Use one canonical request schema (`extra="forbid"`): `user_prompt: str` (max 4,000 chars), optional `aegis_context: list[ContextDocument]` (config defaults: max 4 docs, max 1,500 chars/doc), and `stream: bool = False`. Reject `stream=true`, multi-turn history, extra fields, client-supplied `system`/`tool` roles, or oversized payloads with uniform HTTP 503. Cap raw HTTP body size at 128 KiB (131,072 bytes) by counting bytes as chunks arrive in ASGI middleware BEFORE JSON parsing.
    - `app/schemas.py` uses strict types (no `"true"` to `True` or number to string coercion). Document ids follow the contracts identifier pattern (no `|`) and are unique per request [Project Decision, extends PS-1, PS-3: each id derives its own nonce].
    - `app/middleware.BodyCapMiddleware` is pure ASGI (never `BaseHTTPMiddleware`): a `Content-Length` above the cap, malformed (anything but 1 to 20 ASCII digits, so latin-1 superscripts such as `\xb2` and 5,000-digit values are `body_cap`, never `internal_error`), or conflicting is refused before any body byte is read; otherwise reading stops at the first chunk that pushes the running total past 131,072 bytes (chunked bodies and lying `Content-Length` included). Exactly 131,072 bytes is accepted, 131,073 refused. An accepted body (at most 128 KiB in memory) is replayed to the app unchanged.
    - [TM-R7, TM-R1, LLM10] Rate limiting (Step 5C): `app/rate_limit.RateLimitMiddleware` is a pure ASGI in-memory token bucket (capacity `RATE_LIMIT_RPM`, default 30, refilled at `RATE_LIMIT_RPM / 60` tokens per second on a monotonic clock read inside the lock, with a bucket's last update clamped to `max(clock(), last)` so concurrent or out-of-order readings never rewind it or credit an interval twice (Step 5C.1 L-1), one `threading.Lock`, no `await` inside) registered as the outermost gateway middleware, before the body cap, JSON parsing and every layer: an over-limit request is refused with the uniform 503 (same status, headers and body, so no `Retry-After`) before a single body chunk is read, and logged server-side only as `rate_limit` in `rate_limit_logs` (with `X-Trial-ID` when sent and `target_called=False`). `ENABLE_RATE_LIMITING` unset resolves to true in `production` and `demo` and false in `eval`, `shadow_ingress_only` and `shadow_full_e2e`; `Settings` refuses true in those three measured modes, so rate limiting never distorts E1 to E6, E4 or the concurrency 1, 8 and 32 throughput runs. When E4 or a benchmark runs in another mode, `harness/` must set the flag false and refuse to start otherwise (TM-R7). With `UPSTREAM_MODE=stub` (the local fixed-delay E4 and load-rig upstream) an unset `ENABLE_RATE_LIMITING` resolves to false in every mode and an explicit true is refused at settings validation (Step 5C.1 L-5, TM-R7). `RATE_LIMIT_KEY=ip` (default) keys on the socket peer address (`X-Forwarded-For` is never read); `session` keys on the single well-formed `RATE_LIMIT_SESSION_HEADER` value (default `X-Session-ID`, 1 to 128 visible ASCII characters), never a body field (PS-1); a missing, repeated or malformed header falls back to the peer-address bucket, and a scope with no peer address shares one `anonymous` bucket. The session value is client chosen, so `session` suits a cooperating front end (the demo UI), not an adversary [Project Decision, extends TM-R7]. The bucket store is bounded by `RATE_LIMIT_MAX_CLIENTS` (10,000): idle buckets that have refilled to capacity are dropped first, then the least recently seen client [Project Decision]. Every HTTP request is limited (routing misses and trailing-slash paths included, as each would otherwise reach the body cap) except `GET` and `HEAD` on `/healthz` and `/readyz` [Project Decision]. A fault inside the limiter fails closed as `Error` / `internal_error`, still before the body is read.

4. [IP-1, IP-2, TM-R1] InspectionBundle & Per-View Window Limit: `raw_view` is untouched. `decoded_view` applies Unicode NFKC, strips Unicode category `Cf`, and decodes Base64/hex (depth 2, >=20 chars or padded, >=85% printable UTF-8, including whitespace-joined adjacent candidates). Cap `decoded_view` at 4,000 chars (reuses `MAX_PROMPT_CHARS`). Slice both views into character windows (600 chars, stride 300). If a window exceeds a layer's tokenizer limit (256 for MiniLM, 512 for DeBERTa), split it into sub-windows BEFORE checking the 16-window per-view limit so `truncation_count` remains `0`. Refuse with uniform HTTP 503 ONLY if `decoded_view` > 4,000 chars or windows in EITHER view exceed 16 after sub-window splitting. Never truncate.
    - Frozen schema `contracts/inspection.py` (`InspectionBundle`, `TextWindow`, `WindowPlan`, `DecodeStep`, `CapExceeded`); builder `app/inspection.py`. The schema itself rejects any window whose text is not its view slice, any unscanned gap or tail, more than `max_windows_per_view` windows, and `truncation_count != 0`.
    - Decoding: hex is tried before Base64; a candidate token is a Base64-alphabet run of 20+ characters or one ending in `=`; only adjacent candidates (whitespace-separated) are tried joined, as contiguous runs scanned forward from each position with no piece limit, the longest valid run winning (a neighbouring 20+ character word or path, or a payload split into any number of pieces, cannot hide it). The scan is incremental: Base64 (4 characters to 3 bytes) and hex (2 to 1) decode block by block into a strict incremental UTF-8 decoder, each token is decoded once per start position, and a start stops scanning as soon as its bytes are not UTF-8 or the 85% printable ratio is unreachable even if every remaining character were printable. A run that stops inside a group must end on a Base64 block boundary or `=` padding so the tokens after it start on a fresh block; if no such stop exists the longest run is used anyway (an unpadded payload before an ordinary word), and its continuation is joined without the whitespace gap. Worst case measured in `tests/test_inspection.py` and reported in `CHANGELOG.md`: depth 2 means at most two passes; NFKC plus `Cf` strip runs on the input, on each decoded segment, and at the end of each pass. Not implemented, by spec: cross-script homoglyph folding (optional H-NORM, §3.6), URL percent-decoding, HTML entities.
    - Sub-window splitting [Project Decision, extends IP-2]: each consumer registers a `TokenizerLimit` (name, limit, `count_tokens` including special tokens; the name is checked against `contracts.inspection.TokenizerName` at construction, so bad config fails at startup); a window above the limit is cut into the fewest equal contiguous pieces that all fit, identical pieces from overlapping parents count once, and the 16-window cap is checked per view per tokenizer after splitting. The result is one `WindowPlan` per tokenizer.
    - A cap breach returns `CapExceeded` (`blocked_by` `"decoded_cap"` or `"window_cap"`), logged as `Blocked-ingress`. `bundle_version` is a SHA-256 over `BUNDLE_ALGORITHM_REVISION` (3 since Step 4.6), every bundle parameter including the join-scan mode, the tokenizer limits, and `unicodedata.unidata_version`; `prompt_hash` is `canonical_hash({"raw_view": raw_view})`, and the `InspectionBundle` schema rejects any other value.

5. [IP-9, §3.2, §2.5] Neutral Contracts Package: Shared types live in `contracts/` and import only stdlib and pydantic (zero project imports): canonical gateway modes and `resolve_derivation_mode()` in pure-stdlib `contracts/modes.py` (`GatewayMode`, `DETERMINISTIC_MODES`, `RANDOM_MODES`, so `contracts/` and `app/config.py` never import `app/secret_derivation.py`), frozen `LayerResult` (`layer`, `view`, `per_window_scores` as an immutable tuple, `overall_score`, `verdict` in `allow|block|timeout|error`, `latency_ms`, `truncation_count` == 0, `error_message`), `Outcome(StrEnum)` (`Blocked-ingress`, `Admitted-refused`, `Egress-saved`, `Success`, `Error`), `EgressAction = Literal["none", "masked", "blocked"]`, frozen `RequestLogRecord` (RT-V6 fields plus `blocked_by` using canonical `"L4"` for egress, `egress_variant`, `egress_action` defaulting to `"none"`, `timeout_policy`, `cache_hit`, `model_id`), frozen `ShadowRecord` (IP-4; required non-empty `layer_version`, `bundle_version`, `chroma_version`; `shadow_full_e2e` requires `target_called=True` and all four variants X0 to X3 sharing one `response_hash` and `manifest_id`), frozen `EgressVariantRecord` (required `response_hash` and `manifest_id`, the IP-5 join keys with `variant`, plus `egress_action` defaulting to `"none"`), all SHA-256 fields constrained to `^[0-9a-f]{64}$`, `canonical_hash()` (deterministic JSON with `ensure_ascii=False`, `allow_nan=False`, UTF-8 `surrogatepass` encoding, SHA-256 via `hashlib`; never use Python `hash()`), shared synced-folder path detection in `contracts/paths.py` (`synced_folder_component`), and the typed `TelemetrySink` Protocol (`record_request(RequestLogRecord)`, `record_shadow(ShadowRecord)`) that `app/` layers, middleware, and request handlers call instead of importing `telemetry/`.
    - `target_called` semantics (§3.2, IP-4, IP-5): `target_called=True` means "admitted to the target" even on a response-cache hit (`cache_hit=True`), while `cache_hit` records whether an upstream API call occurred (`False`) or was served from cache (`True`).
    - Strict `outcome` vs `blocked_by` mapping (§3.2): security layer blocks (`L1`, `L2`, `L3`) and input/view/window caps (`body_cap`, `schema_validation`, `decoded_cap`, `window_cap`) map ONLY to `Outcome.BLOCKED_INGRESS` (`target_called=False`); operational and policy faults (`load_shed`, `p_closed`, `timeout`, `upstream_error`, `internal_error`) map ONLY to `Outcome.ERROR` (never `Blocked-ingress`, so overload shedding never inflates block rate); HTTP routing misses (`not_found`, `method_not_allowed`) are not attack outcomes and are excluded from `BlockedBy`; `Outcome.EGRESS_SAVED` requires `egress_variant` in `X1..X3`, `target_called=True`, and `egress_action` in `("masked", "blocked")` (with `blocked_by=None` when `"masked"`, and L4 blocking evidence when `"blocked"`).
    - Layer evidence and oracle consistency (§3.2): `Blocked-ingress` with `blocked_by` in `L1..L3` requires a `LayerResult` of that exact layer with `verdict="block"` (mirroring the L4 rule). When `oracle_result` is recorded, `Success` requires `True` and `Admitted-refused` / `Egress-saved` require `False`. In `EgressVariantRecord`, `verdict="block"` holds if and only if `egress_action="blocked"`, and `X0` (no scan) is always `verdict="allow"`, `egress_action="none"`.
    - `UNPARSED_PROMPT_HASH` (`canonical_hash({"raw_view": None})`) is the `prompt_hash` of a request refused before a prompt was parsed (body cap, schema violation, fault before parsing). A refusal after parsing (config field caps, decoded or window cap, upstream error) logs the real `canonical_hash({"raw_view": user_prompt})`.
    - W2 frozen contracts added at Step 4: `contracts/inspection.py` (IP-1, IP-2), `contracts/cache_keys.py` (IP-5), `contracts/datasets.py` (objective file, translation table, dataset manifest, `CanaryPIIManifest`, the single `PII_ENTITY_TYPES` tuple). Identifiers in these schemas exclude `|`, the PS-3 HMAC field separator [Project Decision, extends PS-3].

    - Cache hits (IP-5, RT-V6; Step 5B.1 LM-2): a replayed `LayerResult` (`model_copy(update={"latency_ms": lookup_ms})`) or `EgressDecision` (`from_cache(..., latency_ms=lookup_ms)`) reports the measured cache lookup time, never the latency stored with the original computation. An egress row written under an older `l4_version` is replaced by the next write under the new version (upsert), so an `L4_REVISION` bump never leaves a key as a permanent miss; within one version the first row is kept.
    - Shadow oracle join contract (IP-4, IP-5; Step 5B.1 LM-4): `shadow_full_e2e` requires `CACHE_ENABLED=true` and `CACHE_WRITES_ENABLED=true` and writes all four egress decisions, X0 included, to the egress cache under `egress_verdict_key(response_hash, manifest_id, variant)` (production does not cache X0). `harness/` fills `EgressVariantRecord.oracle_result` in one of two ways: (a) in process, by calling `app.pipeline.run_shadow_full_e2e_detail(runtime, request)`, which returns the logged `ChatResult` plus, per variant, the verdict, `egress_action`, client-visible `content` (None when blocked or faulted) and the egress cache key, and the shared `response_hash` and `manifest_id`; or (b) offline, by reading each logged `ShadowRecord`, rebuilding the key from its `EgressVariantRecord.response_hash`, `manifest_id` and `variant`, and reading the cached decision's `content` (the L4 version must match). Variant outputs are never logged. Since Step 5C F3 (IP-4, TM-R2, TM-R4), the public HTTP route releases nothing in `shadow_full_e2e`: `POST /v1/chat` always answers with the uniform 503 in both shadow tiers, whatever `EGRESS_VARIANT` and `TIMEOUT_POLICY` say, and `harness/` reads variant outputs only through `run_shadow_full_e2e_detail()` or the cached egress rows.
    - Outcomes (§3.2): a released, unaltered response is `Success` with `oracle_result=None` (the gateway runs no oracle; `harness/` relabels `Success` or `Admitted-refused`). `target_called=True` from the target stage on, including a response-cache hit (`cache_hit=True`) and an upstream failure (`cache_hit=False`).
